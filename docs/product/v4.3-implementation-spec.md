# Melody Garden v4.3 — Viewport UI, Staff Correctness & Session Continuity

**Status:** implementation specification, shipped behind PR review until CI passes.
**Baseline:** v4.2.0-alpha.1. **Scope:** a simple, child-readable app that fits one screen without page-length scrolling, correct treble/bass notation, and safe pause/resume of timed music.

## UX architecture

The application occupies one `100dvh` viewport, with distinct surfaces rather than a long document. Preserve the existing screen IDs and child profiles; upgrade their layout rather than rewrite the game.

- **Home:** header (child, Music Passes, Sparks, Parent), compact companion/mission, daily quest, a visible set of play activities, clef/input controls, and a concise learning panel. Use **Today / Learn** tabs on narrow devices to avoid stacking every dashboard at once. The important next action is always visible. Instruments move to a compact selector rather than a long horizontal row.
- **Workshop:** one visible preview and a compact grid of cosmetics, category buttons remain accessible. Larger catalogues use pagination/filtering rather than a document scroll.
- **Songbook:** viewport-bounded song-grid paging, with previous/next controls.
- **Practice:** score uses the upper flexible area, an optional touch keyboard occupies the lower area, and a fixed top bar hosts Leave, Pause and rhythm information. Game score never gets pushed offscreen.
- **First Concert:** stationary page, keyboard and Save & Leave always in the viewport. Longer scores switch a manual system/page, not automatic scrolling.
- **Results:** succinct celebration, pitch/rhythm summary, Sparks, and Home / Try Again / Workshop. Leaderboard is secondary, capped and collapsible.

Compact phone portrait (390×844), phone landscape (844×390), tablet (768×1024) and desktop (1280×720) must avoid document-level vertical scroll and must keep core controls in the viewport. For extremely tiny screens or when large browser accessibility fonts are requested, prefer a local scrollable *list* or alternate focused panel over clipping information.

## Clef and notation audit

**Root causes (code inspection):** game renderer used separate hand-shaped path transforms for clefs, unlike the static score renderer's system-font glyphs; note Y and ledger loops assumed different clef offsets. Bass note reference was `C3` rather than **G2** at the bottom staff line. Static score rendered `𝄞`/`𝄢` via platform fonts, whose glyph boxes and anchors vary.

**Fix:** a single `notation.js` source for:
- Canonical staff: five lines, bottom = `staffTop + 4 * lineSpacing`; one diatonic step = `lineSpacing/2`.
- Treble bottom line = **E4**; second line = **G4**.
- Bass bottom line = **G2**; second-from-top line = **F3** (bass clef two dots surround F3).
- Notes/ledger lines use the same y-step utility; draw ledger lines only outside the staff (every *second* diatonic step).
- Clef artwork is **embedded SVG outlines** from Noto Music (SIL Open Font License 1.1, attribution), scaled and anchored consistently; no runtime font download or code-point fallback.
- Both scrolling game and stationary score must reuse the same clef asset/geometry. Exercise pitch/spelling is not transposed just to visually match a clef.

**Acceptance examples:** Treble E4 = bottom line; G4 = second line; C4 = ledger below. Bass G2 = bottom line; F3 = fourth line; C3 = second space; C4 = ledger above. Test these as explicit geometry assertions and render examples at each breakpoint.

## True pause/resume

A shared session pause manager should preserve note index, scoring, tempo clock, on-screen notation, audio lifecycle and parent playtime budget.

- **Pause:** freeze the note scroll, timers and missed-note evaluation; stop microphone capture; release app playtime charging while explicitly paused; keep current note and outcome count.
- **Resume:** child explicitly clicks Resume, then a **3-2-1 count-in**. During count-in, touches and mic notes cannot score. Restore clock references by the entire time gap; the beat deadlines shift, and nextBeatTime stays aligned with the original note. Restart microphone capture by a user gesture and fall back to touch input when denied.
- **Leave:** exits safely to Home. Incomplete games/Skill Checks are not scored; auditions continue to use their already implemented durable Save & Leave checkpoints.
- **Background:** auto-pause rather than exiting. On return show the paused overlay, not a surprise restart.
- **Parent:** opening settings during a game should also pause, returning to a paused state.
- **Session safety:** cancel pending callbacks by token and phase; no duplicate reward grants; do not reset score during pause/resume.
- **Music Pass:** explicit pause and background time never count, but count-in is an intentional gameplay moment; allowance expiry still uses the existing bounded musical checkpoint grace.

### Engineering boundaries

- `js/notation.js`: pure geometry and SVG clefs.
- `js/score.js`: fixed notation based on shared geometry; separate score model from playback timeline.
- `js/game.js`: pause/resume integrated into existing standard and timed loops with a shared logical clock.
- `js/session-pause.js`: deterministic state for freeze/resume delta, pure test harness.
- `js/ui.js`: compact app layout and paging, no unrelated scoring logic.
- `styles.css`: viewport grid and responsive layout, reduced-motion support.
- `tests/` / `e2e/`: geometry, timer, resume and viewport regressions.

## Definition of done

1. Render correct clefs and ledger lines for canonical treble and bass reference pitches, in both game and static scores.
2. Home, game, audition, results and store primary flows are operable without a **page-length** scroll at all target sizes.
3. A timed Pro Coin Run resumes from the *same note index*, no missed beats while paused, and shifted deadlines after count-in.
4. A timed Song resumes without increasing the elapsed playing time by the pause duration; repeated pause/resume does not duplicate intervals.
5. Hidden/background tab and Parent Zone do not silently discard a game, and microphone tracks stop during pauses.
6. Music Passes stop consuming time during explicit Pause; resume obeys remaining budget.
7. Existing v4.2 audition resume, Workshop, profiles, learning and microphone E2E tests remain green.
8. A new independently playable **two-staff piano score** contains paired treble and bass voices with stable SVG glyphs, human/teacher observed practice, and manual pagination. It does **not** fabricate polyphonic microphone grades.
9. Advanced Grade-8-complexity automatic polyphonic assessment remains beyond the current microphone, so evaluate any future system separately with physical instruments and valid repertoire.
