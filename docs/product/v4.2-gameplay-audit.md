# v4.2 Gameplay & Learning Journey Audit

Status: **Source-code UX audit and browser-test review**, not a substitute for hands-on child playtesting.

## Most important observed problems

| Flow | Observed in v4.1 | v4.2 action | Status |
|---|---|---|---|
| Audition exit | The Back control silently destroyed the current audition session | Replace with **Save & Leave**, checkpoint after every note, restore same excerpt/index after reload | Implemented |
| Audition retake | Returning to First Concert always restarted from note 1 | Home says **Resume my concert**; intentional Restart requires confirmation | Implemented |
| Wrong-note handling | Could leave child stuck without clear options | Gentle retry explanation, visible Skip Note, preserved first-try state | Implemented |
| Audition progression | Only harder/finish after completing a phrase | Add **Another melody**, optional stretch challenge, provisional placement | Implemented |
| Parent time limits | An interrupted audition was not scored, but resume was not possible | Save partial audition rather than treating as a failure; Music Pass time policy unchanged | Implemented |
| Practice transfer | Adaptive note-by-note drill did not teach reading whole phrases | New **stationary phrase practice**, no moving staff or key-following | Implemented |
| Assessment validity | Separate v3.2 note checks but no independent musical phrase check | New, mastery-blind **fresh phrase check** with separate results | Implemented |
| Guidance removal | Virtual keyboard labels reveal pitches | Keyboard labels hidden in phrase modes; reveal only on request during practice | Implemented |
| Parent interpretation | Progress largely reported notes practiced and Skill Checks | Add phrase-check outcome and recommended spaced-review note to Parent Zone | Implemented |
| Playtime navigation | Old ❌ implied closing abruptly | Explicit **Leave** label and clarification that incomplete ordinary rounds aren't scored | Implemented |
| General game pause | Legacy scrolling practice has no safe pause/resume state for timed performances | Needs a proper pause/resume session state machine | Deferred |
| Advanced notation | Current static SVG cannot engrave realistic full two-hand scores | Evaluate conventional grand-staff renderer with original content and human-assisted checks | Deferred |

## Child-facing acceptance questions

1. Can each child deliberately leave First Concert in the middle, then return tomorrow and **start at the same note**?
2. If a note was missed before leaving, does the first-try score correctly remain affected after return?
3. Can a child choose another audition melody or a harder piece without being stuck in a low-level loop?
4. Is a complete phrase visible on screen before playing? Does it remain stationary while the child plays?
5. Can a child understand the difference between practice with hints and independent checking?
6. When a daily Music Pass ends, does the current audition remain resumable and an incomplete check remain unscored?
7. Are siblings' progress, limits, preferred clefs, and phrase histories isolated?
8. Does the parent understand whether results came from guided note naming or genuinely fresh phrase reading?

## Score and progression honesty

- The generated v4.2 phrases are **monophonic 4/4 melodies** with complete bars. They are a bridge to independent sight-reading, not Grade-8-level full piano repertoire.
- Upper in-app levels remain aspirational until a polyphonic engraving engine, original graded repertoire and a validated evaluation method exist.
- Independent phrase results are recorded separately from adaptive note mastery; returning to a repeated phrase does not constitute transfer evidence.
- Acoustic microphone estimates are approximate and not independently validated for complicated dynamics, sustain pedal or two-hand chords.

## Recommended next user-testing session

For each child, conduct a supervised 10–15-minute walkthrough, with a 5-minute cap if preferred: open their profile, start a concert, play 2–4 notes, leave, do something else, return, open a stationary phrase, and finish or stop. Observe hesitation, mis-taps, score readability, whether they recognize the Save & Leave control, and whether they understand feedback. Then try on an actual piano with the device microphone. Record problems before adding larger map/story mechanics.

## Suggested engineering follow-up

- **P0**: ensure these v4.2 exit/reload/mobile and blind-check regressions pass on CI.
- **P1**: shared session pause/resume state machine for all modes, especially timed songs; clear leave/retry semantics.
- **P1**: improve stationary notation layout and keypad accessibility on low-width phones.
- **P2**: true piano grand-staff engraving, page navigation, original advanced phrases and honest optional teacher assessment.
- **Research**: measure independent unseen-phrase improvement and retention, not simply longer engagement or faster tap scores.
